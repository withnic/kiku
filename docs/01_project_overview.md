# **01\_project\_overview — 規矩（kiku）**

# **1\. プロジェクトの目的と背景**

## **背景と課題**

Google の `go-yaml` や標準的な YAML シリアライザ・フォーマッタを通すと、以下のような問題が発生し、「人間が日常的に読み書き・メンテナンスする設定ファイル（辞書・ルール定義・インフラ設定等）」の品質を著しく損なう。

1. **コメントと意図的な空行の消失・破壊**: 行頭コメント・インラインコメント・セクション間の空行が削除されたり位置がずれたりする。  
2. **表記ゆれの放置と混在**: 同じ意味の配列（Sequence）に対して、フロースタイル（`[a, b]`）とブロックスタイル（`- a`）が同一ファイル内で混在しても検知できない。また、`yamllint` は指摘のみで自動修正（Fix）を持たず、`yamlfmt` は人間向けのスタイル統一ルール（配列混在検知やクォート・真偽値正規化）を持たない。  
3. **クロスプラットフォームでのファイル衛生の乱れ**: Windows と WSL2 / Linux を往復する環境において、UTF-8 BOM の混入、CRLF/LF の混在、行末空白、ハードタブ混入などが発生しやすい。

## **目的**

**「規矩（kiku）」**（規＝コンパスで測り基準を示す Linter、矩＝さしがねで直角に正す Fixer）は、**コメントと意図的な空行を完全に保持したまま**、YAML の構文検証（Lint）と人間が読みやすい形式への自動整形（Fix）を単一バイナリで完結させる Go 製 CLI ツールである。

# **2\. 全体ワークフロー**

1. **対象パスと除外指定の仕組み**:  
   * **対象指定**: CLI 引数（`kiku check [paths...]` / `kiku fix [paths...]`）で任意のファイルや複数ディレクトリを直接指定可能（引数省略時は `.kiku.yaml` の `include`、それも未指定ならカレントディレクトリ `.` を走査）。ディレクトリ走査時は拡張子 `.yaml` / `.yml`（大文字小文字不問）のファイルのみを対象とし、CLI 引数でファイルパスを直接指定した場合は拡張子に関わらず対象とする。  
   * **全体除外（ファイル・ディレクトリ・正規表現）**: `.kiku.yaml` のトップレベル `ignore`、`.kikuignore` ファイル（1行1パターン）、および CLI オプション `--ignore <pattern>`（複数指定可）で、特定のファイル名、ディレクトリ（`dir/**`）、グロブ、正規表現（`re:<regex>` 形式）による除外が可能。  
   * **ルール別除外（Per-Rule Ignore）**: `.kiku.yaml` の各ルール設定（`rules.<rule>.ignore`）ごとにグロブおよび `re:<regex>` で除外対象ファイルを指定でき、「特定のファイル群だけ `sequence_style` や `line_length` を適用除外にする」といった柔軟な運用が可能。  
2. **設定ファイル解決（`.kiku.yaml`）**: `--config <path>` が明示指定された場合はその設定ファイルのみを使用する。未指定時は、対象パス解決（`include` 参照）のためにカレントディレクトリから親へ遡って `.kiku.yaml`（または `kiku.yaml`）を探索し、さらに各ファイルの処理時は対象ファイルのディレクトリから親ディレクトリへ遡って最も近い設定ファイルを適用する。見つからない場合は組み込みのデフォルト設定（ゼロコンフィグ）を適用する。  
3. **2層検証パイプライン（Layer 1 → Layer 2）**:  
   * **Layer 1（YAML 1.2 仕様準拠・常時有効・オンオフ不可）**: UTF-8 不正バイト列、ハードタブ（`\t`）インデント、同一マッピング内の重複キー、構文エラーを検知する。`kiku fix` 時は、インデントのハードタブのみ設定されたインデント幅の半角スペースへ自動変換して救済し、重複キー・構文エラーはデータ破壊防止のため自動削除せずエラー報告してスキップする。  
   * **Layer 2（スタイル・可読性ルール・`.kiku.yaml` で全項目オンオフ可能）**: 改行コード（LF/CRLF）、BOM除去、行長制限、インデント幅、配列スタイル（`block` / `flow` / `consistent` / `hybrid`）、クォート正規化、真偽値統一、Null表記統一、コメントスペース整形、空行圧縮、行末空白除去、末尾改行、およびオプションのキーソートを実行する。  
4. **インライン無視ディレクティブ評価（行・ブロック・段落・範囲スキップ）**: `golangci-lint` の `//nolint` と同様に、`# kiku:ignore`（および `# kiku-disable`）系コメントを解析し、「同一行（行末）」「次の行／ネストしたブロック全体（インデントが戻るまで）」「空行で区切られた1段落（`# kiku:ignore-section`）」「`disable`〜`enable` 範囲」の4つの粒度で Layer 2 ルールの指摘および自動修正をスキップする（`-- 理由` の付記にも対応、Layer 1 の仕様違反は無効化不可）。  
5. **出力・書き戻し**:  
   * `kiku check`（Lint モード）: 違反一覧を `text` / `json` / `github` 形式で標準出力へ出力し、違反があれば終了コード `1` を返す。  
   * `kiku fix`（Fix モード）: `--diff` 指定時は Unified Diff を出力、`--stdout` 指定時は単一ファイルの整形結果を標準出力へ出力（いずれも元ファイルは上書きしない）。通常時は一時ファイル経由のアトミック書き込み（`line_endings` 有効時は設定の改行コードへ統一、無効・除外時は元の改行コードを維持し、ファイルパーミッションを保持）で安全に上書きする。

# **3\. MVP スコープ（初期リリース必須要件）**

「人間が読んで気持ちいい状態に一通り整うセット」を初期バージョン（v0.1.0）からすべて網羅する。

## **3.1 必須搭載機能（MVP）**

* **CLI サブコマンド**: `kiku check`、`kiku fix`、`kiku init`（デフォルトの `.kiku.yaml` 生成）、`kiku version`。パス指定（`paths...`）、CLI除外指定（`--ignore <pattern>`）およびルール別除外設定（`rules.<rule>.ignore`）に対応。  
* **Layer 1 仕様準拠チェック（常時有効・オンオフ不可）**:  
  * `syntax-error`: `goccy/go-yaml` による YAML 1.2 構文チェック  
  * `invalid-utf8`: 不正な UTF-8 シーケンス検知  
  * `no-tabs`: インデント内のハードタブ検知（`fix` 時はスペース置換で自動救済）  
  * `key-duplicates`: 同一マッピング内の重複キー検知（`fix` 時は安全のため自動修正せずエラー維持）  
* **Layer 2 スタイル・可読性ルール（すべて `.kiku.yaml` で個別 `enabled: true/false` 可能）**:  
  * デフォルト有効（`enabled: true`）:  
    1. `encoding`（UTF-8 BOM 検知・除去 `forbid_bom: true`）  
    2. `line-endings`（`lf` / `crlf` 統一、デフォルト `lf`）  
    3. `line-length`（最大文字数チェック、デフォルト `120`、`ignore_comments` / `ignore_urls` 対応）  
    4. `trailing-whitespace`（行末空白除去）  
    5. `final-newline`（ファイル末尾の単一改行保証）  
    6. `blank-lines`（連続空行の上限圧縮、デフォルト `max_consecutive: 1`）  
    7. `indentation`（インデント幅統一、デフォルト `2` スペース）  
    8. `sequence-style`（配列スタイル統一：`block` / `flow` / `consistent` / `hybrid`、空配列 `[]` 許可オプション付）  
    9. `quotes`（不要クォート除去・優先クォート `double` / `single` 統一、予約語や数値文字列の誤解釈防止保護付）  
    10. `truthy`（非クォートの `yes`/`no`/`on`/`off`/`True`/`FALSE` 等を小文字 `true`/`false` に統一）  
    11. `null-style`（`empty` / `null` / `tilde` の統一、デフォルト `empty`）  
    12. `comments`（`#` 後の半角スペース強制、インラインコメント前の最小スペース数統一）  
  * デフォルト無効（`enabled: false`、設定で有効化可能）:  
    13\. `document-start`（先頭 `---` の強制または禁止）  
    14\. `sort-keys`（マッピングキーの昇順ソート、`recursive` オプションおよびルール別 `ignore` 対応）  
* **コメント＆空行の完全保持エンジン**:  
  * 行頭コメント、ブロック間コメント、インラインコメント、ファイル末尾コメント、およびセクション区切りの空行を一切欠落させずに AST / トークン位置ベースで再構築する。

## **3.2 スコープ外（Non-Goals）**

* JSON Schema によるドメイン固有の値バリデーション（型チェックや業務ロジック検証）  
* YAML 1.1 独自仕様（`<<` マージキーの展開や暗黙の8進数変換など）のエミュレーション  
* GUI / LSP サーバーの常駐プロセス実装（将来拡張とし、MVP は高速なワンショット CLI に徹する）

# **4\. 非機能要件**

* **パフォーマンス**: 1,000 行規模の YAML ファイル 100 件の `check` / `fix` を 500ms 以内に完了すること。  
* **シングルバイナリ・外部ツールゼロ依存**: Go 1.23+ でビルドし、外部ランタイムや外部コマンドなしで Windows 11 / WSL2 / Linux / macOS で単体動作すること。  
* **データ安全性（ゼロデータロス）**:  
  * 構文エラーや重複キーを含むファイルは `kiku fix` でも絶対に上書きしない。  
  * 書き込み時は同一ディレクトリへの一時ファイル作成＋リネームによるアトミック置換を行い、途中で異常終了しても元ファイルを破損させない。  
  * 修正後の出力を必ず内部で再パース（ラウンドトリップ検証）し、意味的等価性（AST のデータ値およびコメント内容の不変性）が保証されない場合は書き込みを中断してエラー終了する。  
* **クロスプラットフォーム一貫性**: Windows（CRLF / パス区切り `\`）と WSL2 / Linux（LF / パス区切り `/`）のどちらから実行しても同一の判定結果・フォーマット結果を出力すること。
